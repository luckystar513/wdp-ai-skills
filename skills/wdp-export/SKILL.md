# /wdp-export — 导出为 AGENTS.md

把 wdp 存储的 **profile（稳定层）+ 最新快照（工作状态）** 合成一份 **AGENTS.md 兼容**的上下文文档，写入项目根目录，让**其他 coding agent**（不认 /wdp-* 命令的）在启动时自动读到。

**用途**：`/wdp-init` 是"人/本工具内接续"；`/wdp-export` 是"把上下文带给不认识 wdp 的 agent"。

## 存储根目录（所有 wdp 命令共用）

1. 若本技能目录存在兄弟目录 `wdp-sum`（即 `../wdp-sum/summaries/`），优先使用它；
2. 否则回退到 `~/.claude/skills/wdp-sum/summaries/`。

## 执行步骤

### 1. 确定项目
- 无参数：当前工作目录（`pwd`），导出到 `<pwd>/AGENTS.md`。
- 有参数：`/wdp-export <项目路径>`，导出到 `<项目路径>/AGENTS.md`。

### 2. 读取两层数据
- 读 `<存储根>/<项目slug>/profile.md`（若存在）；
- 读 `latest.md` 指向的最新快照（或按时间戳取最新）；
- **任一层缺失**：提示缺少的部分，用现有部分导出，并在 AGENTS.md 中标注"该节尚未维护"。

### 3. 合成 AGENTS.md（合并策略，绝不丢用户内容）
- 目标文件 `<项目根>/AGENTS.md`。
- 若不存在：创建，全文为 wdp 生成内容。
- 若已存在：
  - 含 `<!-- wdp-export-begin -->` 与 `<!-- wdp-export-end -->` 标记 → 仅**替换标记之间**的内容（说明这是 wdp 维护区，其余保留）；
  - 不含标记 → **在文件末尾追加**一段 wdp 维护区（用标记包裹），不触碰已有内容，并提示用户已追加。
- 生成内容用 `<!-- wdp-export-begin -->` / `<!-- wdp-export-end -->` 包裹，便于下次增量更新。

### 4. 内容模板（紧凑，AGENTS.md 宜短）
```markdown
<!-- wdp-export-begin -->
# Project Context (auto-generated by wdp /wdp-export)

## What / Quick summary
<一句话定位 + 业务领域，来自 profile>

## Tech stack
<语言/框架/关键依赖>

## Architecture (top-level)
<模块边界、入口、数据流，3-6 行>

## Invariants (must not break)
<profile 的不可违背规则逐条列出>

## How to run
<build / test / run / deploy>

## Current work state (as of <快照时间>)
- 当前焦点：<…>
- 进行中：<…>
- 下一步：<前 3 条>
- 最近完成：<…>

## Known gotchas / Decisions
<来自 profile 的坑与决策，各 2-4 条>
<!-- wdp-export-end -->
```
- **不写**密钥、凭据内容（只可写"凭据位置"）；
- **不写**完整快照历史，只写最新状态 + 最近要点；
- 保持紧凑：目标是让 agent 一读即懂，不是存档案。

### 5. 报告结果
- AGENTS.md 路径；
- 新建 / 替换维护区 / 追加维护区（哪种操作）；
- 哪些节因数据缺失被标注。

## 常见错误

| 错误 | 修正 |
|------|------|
| 覆盖用户已有的 AGENTS.md | 有标记只替换维护区，无标记追加，绝不整文件覆盖 |
| 把密钥/完整快照历史写进去 | 只写位置与最新状态，AGENTS.md 是给 agent 看的导览，不是存档 |
| 只导 profile 不导工作状态 | 其他 agent 启动最需要"现在做到哪了"，两层都要 |
| 忘记标记 | 没标记下次无法增量更新，会重复追加 |
