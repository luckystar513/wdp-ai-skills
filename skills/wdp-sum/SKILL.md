# /wdp-sum — 记录工作快照

把当前项目的**工作状态**固化成一份带时间戳的**快照**（追加式，不覆盖历史），供下次启动的 agent 用 `/wdp-init` 快速接续。

**核心原则：稳定信息归 profile，易变信息归快照。** `/wdp-sum` 只写快照层；稳定层（技术栈/架构/业务/规则）由 `/wdp-profile` 维护，快照里通过 `profile:` 引用它，**不要重复粘贴技术栈**。

## 存储模型

```
<存储根>/<项目slug>/
├── profile.md            # 稳定层（/wdp-profile 维护）
├── <YYYY-MM-DD_HHMMSS>.md  # 快照层（本命令追加）
└── latest.md             # 指向最新快照
```

## 存储根目录（所有 wdp 命令共用）

1. 若本技能目录存在兄弟目录 `wdp-sum`（即 `../wdp-sum/summaries/`），优先使用它；
2. 否则回退到 `~/.claude/skills/wdp-sum/summaries/`。

目录不存在时先创建。

## 执行步骤

### 1. 确定项目
- 无参数：以当前工作目录（`pwd`）作为项目。
- 有参数：`/wdp-sum <项目路径>` 时，用给定路径。
- 带 `--deep`：进入**深度模式**（见下节），派生子 agent 逐子系统深挖后综合成更完整的快照。

### 2. 读取上一份快照（增量基础）
- 定位 `<项目slug>/` 目录，按文件名时间戳排序取最新一份（若存在）；
- 若存在 `latest.md`，以它为准；
- 上一份快照的"进行中 / 下一步"是本次快照的对比基准。

### 3. 收集信息（只读探索，不要修改项目文件）
- **git 状态**（若在仓库）：`git status --short`、`git branch --show-current`、`git log --oneline -10`、`git diff --stat`。
- **自上次以来的变化（增量对比，核心步骤）**：
  - 逐条核对上一份快照的"进行中 / 下一步 / 当前焦点"；
  - 每条标注状态：✅已完成 / 🔄仍进行中 / ⛔已放弃 / 🔀变更方向；
  - 对仍进行中的条目，写清**新进展**（不是重复旧描述）；
  - 用 git diff 佐证（改了哪些文件、提交了哪些）；
  - **若某条与上次完全一样、无任何新进展，标"（较上次无变化）"**，不要臆造进展。
- **任务列表**：若本会话有 TaskList，按其状态归纳。
- **本次会话的非显然知识**：踩过的坑、反直觉结论、推翻的假设——从本次实际工作中提取，不要编造。

### 4. 生成快照文档
用下面的**模板**撰写。frontmatter 必须完整填写（`prev` 指向上一份快照文件名，`profile` 指向 profile.md，若 profile 不存在则写 `profile: ~` 并在报告中提示先用 `/wdp-profile`）。

## 快照模板

```markdown
---
type: snapshot
project: <项目slug>
created: <YYYY-MM-DDTHH:MM:SS>
author: <agent名>
commit: <git hash 或 ~>
prev: <上一份快照文件名 或 ~>
profile: <profile.md 或 ~>
tags: []
---

# 工作快照 · <项目名>

## 当前焦点
<一句话：为什么现在在做这件事>

## 自上次以来完成（Done since last）
- ✅ <要点>

## 进行中（In progress）
- 🔄 <要点，含阻塞/风险>（新增进展：…；或标注"较上次无变化"）

## 变更方向 / 放弃（Changed / Dropped）
- ⛔ <原计划事项> → 放弃/变更原因

## 下一步（Next 3-5）
- <按价值排序>

## 本次会话的非显然知识（Non-obvious learnings）
- <踩过的坑、反直觉结论、推翻的假设>

## 关键决策与理由（Decisions & why）
- <What + Why，防重蹈覆辙>
```

### 5. 更新 latest.md
把 `latest.md` 内容更新为最新快照文件名（一行）。

### 6. 报告结果
- 文档保存路径；
- 一句话概述（项目、当前状态）；
- 若 `profile.md` 不存在，提醒用户运行 `/wdp-profile` 生成稳定层。
- 若是 `--deep` 模式：注明分析过哪些子系统、派生了几个子 agent。

## 深度模式（/wdp-sum --deep）

**显式 opt-in**，仅在用户明确带 `--deep` 时启用（比普通快照更耗 token）。让快照从"会话视角"升级为"全项目视角"——适合里程碑收尾、长期未总结、或跨多个子系统的大改动后。

### 执行流程

1. **划分子系统**：从 profile 的架构概览 + 目录结构，把项目划分为 **2-5 个子系统**（过细会放大成本）；无 profile 时直接从目录结构划分。
2. **并行派生子 agent**（Agent 工具），每个子系统一个，只读分析：
   - 该子系统的**当前状态**：最近变更（git 佐证）、完成/进行中/阻塞项；
   - 与上一份快照的**出入**：哪些条目过时、哪些新出现；
   - **非显然问题**：坑、反直觉结论、技术债。
   - 要求子 agent：只读，不修改任何文件，返回结构化要点（每项 ≤ 1-2 行）。
3. **可选：一个全局 agent** 扫跨切面（完整 git log 分析、TODO/FIXME/XXX 密度、整体健康度）。
4. **综合**：把各子系统结论按快照模板合成为一份**更深的快照**——"当前焦点"体现全局判断，"进行中/下一步"覆盖每个子系统，`tags` 加 `deep`，frontmatter 照常。
5. 更新 `latest.md`、报告结果，与普通模式相同。

### 注意

- 派生子 agent 前**先确认用户愿意等**（并行分析通常 1-3 分钟）；用户反悔就退回普通模式。
- 子 agent 的结论若与主会话已知事实冲突，以代码/git 实际为准，并标注冲突点。
- 深度快照仍然**不写稳定层信息**（技术栈/架构归 profile），只让"状态层"更全面。

## 主动触发约定（关键时刻主动建议）

本会话后续发生以下情况时，**主动**建议运行 `/wdp-sum` 保存快照（与 `/wdp-init` 的"会话开始约定"形成闭环，让 wdp 从手动工具变成自动记忆）：

- 完成了**里程碑**或**重大改动**；
- 会话上下文即将被**压缩 / 清空**（`/clear`、上下文明显过长）；
- 即将**切换 agent / 关闭会话 / 交接他人**；
- 一段**长时间工作**收尾（一个子任务完结、一项调查结束）。

一句话提醒即可，不必打断当前流程。例："已完成 X，建议运行 `/wdp-sum` 保存快照，下次 `/wdp-init` 即可接续。"

## 常见错误

| 错误 | 修正 |
|------|------|
| 把技术栈/业务写进快照 | 稳定信息归 `/wdp-profile`，快照只写状态变化 |
| 覆盖上一份快照 | 文件名带时间戳追加，永不覆盖 |
| 忽略 git diff / 上份快照 | 增量对比是快照的价值来源 |
| frontmatter 缺 `prev`/`created` | 缺了 `/wdp-init` 无法做增量接续 |
| 普通模式误派子 agent | `--deep` 是显式 opt-in，未带该参数就只做会话级总结 |
